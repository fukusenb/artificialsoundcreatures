# カエル合唱シミュレーター (Artificial Sound Creatures)

合原モデル（ニホンアマガエルの位相振動子モデル）を、実機ハードウェアの制約に
合わせて **パルス結合振動子 + 音量ゲート + 位相応答曲線(PRC)** として実装した
PC 内シミュレーターです。展示前にパラメータ（結合強度・固有周期のばらつき・
近傍音量閾値など）を追い込むための道具として使います。

## なぜこの形か

教科書的な合原・蔵本モデルは各振動子が隣の連続位相 `θ_j` を知っている前提ですが、
実機はマイク 1 個で **全個体の混合音** を聞くだけで個々の位相は取れません。
そこで本物のカエルと同じく「**鳴き声（離散イベント）を聞いて自分の位相をずらす**」
パルス結合として実装しています。AI 識別器の役割は、混合音を
「近くでカエルが鳴いた + その音量」という離散イベントに変換することです。

- 各個体は内部位相 `phi in [0,1)` を固有周期 `T` で進め、`phi>=1` で発声・リセット。
- 他個体の声は距離で減衰した音量として届く（`heard = A0 / (1 + (d/d0)^2)`）。
- 音量が閾値 `loudness_gate` 以上のイベントにだけ PRC で応答（＝近い個体とだけ結合）。
- PRC `Δphi = sign * K * sin(2π phi)` の `sign=+1`（反発/抑制的）で、
  2 体は位相差 0.5（= π, 逆相）が安定点になる。
- 発声直後は `refractory` 期間マイク判定を無効化（自己フィードバック遮断）。

## 実行

```bash
pip install -r requirements.txt
python run_demo.py          # out/ に PNG を出力
python run_demo.py --show   # GUI 環境なら画面表示も
```

## 出力される図

| ファイル | 内容 |
|---|---|
| `out/two_frogs.png` | 2 体が位相差 0.5（逆相 π）へ収束する様子 |
| `out/chain_frogs.png` | 1 次元（畦に並ぶカエル）: 最近傍が交互鳴き |
| `out/field_frogs.png` | 2 次元ランダム配置: フラストレーションで動的な局所クラスター |

## 主要パラメータ（`frog_chorus.Config`）

| 項目 | 意味 | 効かせ方 |
|---|---|---|
| `coupling` (K) | 結合の強さ | 弱すぎ→揃わない / 強すぎ→硬直。0.1〜0.3 が目安 |
| `prc_sign` | +1 反発（逆相） / -1 引力（同相） | 逆相合唱なら +1 |
| `period_mean` / `period_spread` | 固有周期と個体差 | ばらつきを入れると挙動が豊かに |
| `loudness_gate` | 近傍とみなす音量閾値 | 実質的な「相互作用の届く距離」 |
| `coupling_mode` | `"all"` 音量重み / `"nearest"` 最近傍1体のみ | 「1 体と π」を強めるなら nearest |
| `refractory` | 発声後にマイクを無効化する時間 | 自己発火の暴走防止 |
| `detection_latency` | AI 検出遅延 | 実機の 0.3〜0.5s を入れて頑健性確認 |

## 実機への移植

`frog_chorus.simulate` のメインループ内、1 個体ぶんの処理（自然進行 → 発声判定 →
イベント受信 → PRC 適用）がそのまま XIAO ESP32S3 Sense 上の C++ ループに対応します。
`loud[l, f]` による音量計算は実機ではマイクの実測音量に、`frog_detected()` は
DS-CNN の判定結果に置き換わります。ここで固めたパラメータを移植の初期値にします。
